# PRD — 辰知教务

## 产品目标

为中小型培训机构 / 教务部门提供一套一体化的课务后台，把「学员、教师、课程、班级、排课、考勤、成绩、收费」收敛进同一系统，并以**课时余额**为业务主线，实现从缴费到消课的闭环管理。同时作为 `@homurajs` 六模块全家桶的端到端参考实现。

## 用户与使用场景

- **目标用户（按角色）**：
  - **超级管理员（admin）**：全权限，管账号、授权、系统设置。
  - **教务（academic）**：管学员/班级/排课/考勤/成绩，看营收但不改财务。
  - **教师（teacher）**：看自己的课表与班级，登记考勤与成绩。
  - **财务（finance）**：管订单收费、看营收报表。
  - **只读（viewer）**：新注册账号的缺省角色，只能查看。
- **典型场景**：
  1. 前台为新生建档、分班、开缴费单充值课时。
  2. 教务按周排课，系统自动检测教室/教师冲突。
  3. 教师上课点名，出勤自动扣减学员课时余额，余额不足触发预警。
  4. 财务查看月度营收、课程排行；管理员在设置页调整用户角色、查看授权状态。

## 核心问题

| 痛点 | 现状 | 本产品如何解决 |
|------|------|----------------|
| 课时对不上账 | 缴费、上课、消课分散在 Excel/纸质，余额靠人工推算 | 余额由订单充值、考勤扣减**系统联动**，全程可追溯 |
| 排课撞车 | 同教室/同教师时段冲突靠人脑记 | 排课时三维冲突检测（教室∪教师 × 节次区间 × 教学周段） |
| 权限粗放 | 谁都能改数据 | RBAC 五角色 × 细粒度权限点，前后端双重门控 |
| 数据无洞察 | 看不到营收/出勤趋势 | 仪表盘聚合：营收月序、出勤率、课时预警、课程排行 |

## 功能及其意义

| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| 工作台（仪表盘） | 运营概览 | 一屏掌握学员/班级/营收/出勤/预警，决策入口 |
| 学员管理 + 个人档案 | 学员全生命周期 | 建档、分班、余额、考勤/成绩/订单聚合到一人 |
| 教师管理 | 师资台账 | 教师信息、任教学科、带班数、个人课表 |
| 课程管理 | 课程目录 | 课程/代码/单价/课时/配色，供班级与订单引用 |
| 班级管理 + 成员 | 教学组织单元 | 班级绑定课程/教师/教室，容量约束，成员进出 |
| 周课表（排课） | 可视化课表 | 节次×星期网格，课程色卡片，按教学周过滤 |
| 考勤点名 | 消课与出勤 | 按班级节次点名，出勤联动扣课时，出勤率统计 |
| 成绩管理 | 学业记录 | 考试成绩、平均分，归集到学员档案 |
| 收费订单 | 营收与充值 | 下单充值课时、支付/退款状态流转、营收统计 |
| 课表（三维度） | 可视化课表 | 全局/教师/班级周课表网格，教学周由学期解析 |
| 调换课 | 单次课变更 | 按具体日期停课/代课/对调，例外层叠加到循环排课 |
| 自动派课 | 批量排课 | 贪心+回溯为多班批量生成无冲突排课，可配星期/节次/教室池 |
| 学期管理 | 时间锚点 | 学期起止/总周数，驱动日期↔教学周解析与课表周次 |
| 资料库 | 文件管理 | 课件/讲义上传下载（对象存储 + 代理路由） |
| 系统设置 | 账号与授权 | 学期管理、RBAC 角色管理、授权状态、系统信息 |
| 认证会话 | 访问控制 | 密码登录、JWT 会话自动续期、登出失效 |

## 功能之间的关系

```
学期 ──> 日期↔教学周解析 ──┐
课程 ──┐                   │
教师 ──┼──> 班级 ──> 排课(循环) ──┬──> 课表(全局/教师/班级周视图)
       │        ↑                │
学员 ──┴────────┘（班级成员）    ├──> 调换课(例外层: 停课/代课/对调，按具体日期)
  │                             └──> 考勤点名 ──┐
  │   自动派课(贪心+回溯)──批量生成──┘           ├─> 学员个人档案
  └──> 订单(充值课时余额) ──────────────────────┘
                    余额被考勤扣减 ↑↓ 被订单充值
  全部 ──> 工作台仪表盘（聚合统计）
  授权(license) ──> 守卫全站 /api（停服时仅登录链与状态页可达）
  RBAC(profiles) ──> 门控每个功能的读/写/删
```

核心枢纽是**学员**与**课时余额**：订单充值余额、考勤扣减余额，二者共同构成消课闭环；班级是课程/教师/排课/成员的组织单元；**学期**是日期↔教学周的锚点，课表周次、调换课的具体日期、自动派课的教学周段都依赖它；**排课**分两层——循环排课（按周重复）+ 例外层（调换课，针对具体某一次课），单日课表由二者叠加解析；仪表盘对所有实体做聚合。

## 范围与非目标

- **范围内**：上述 15 个业务域的单机构/单租户管理；密码登录 + RBAC；本地授权守卫；local-fs 文件存储；sqlite（缺省）/ pg（备选）持久化；**学期驱动的日期↔教学周**；**三维度课表**；**调换课（停课/代课/对调）**；**自动派课（贪心+回溯）**。
- **范围外（明确排除）**：
  - 第三方 OAuth2 / SSO 登录（SDK 支持，本产品未接）。
  - 真实在线支付、发票、对账（订单金额手工录入）。
  - 多租户 / SaaS 数据隔离、跨机构协作。
  - 家长端 / 学员端小程序、消息推送、短信通知。
  - **走班排课**（学生个性化课表、分层走班）与**复杂约束求解**（教师时间偏好、连堂硬约束、跨班互斥的最优解 CSP/求解器）——当前自动派课是贪心+回溯的可行解，非全局最优；手动排课 + 三维冲突校验仍是主路径。
  - 生产级中央授权服务（用本地 genuine-mock 演示 license 链路）。
